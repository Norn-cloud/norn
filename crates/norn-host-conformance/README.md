# Native host conformance

HOST-CONFORMANCE-1 keeps cross-boundary integration in non-publishing Cargo test
targets with development dependencies only. The persisted-perform property runs
the real metrics Function through SqliteCell, checks recorded receipts and refuses
wrong scope/table/blob pins. The analytics library keeps its IR/checker boundary.

The CSV/PUBLISH fixture admits the typed declarations and uses the pinned
scrap-yield CSV, authenticated incarnation exports, native Function execution and
the governed PUBLISH action. The forecast's gram properties declare the exact
core unit-catalog dependency, and fixture admission includes that retained catalog.
The timed world publishes. The October 26 bulk world
refuses with `core.projection.publication_guard` and temporal-leakage detail,
retains its unconsumed receipt and writes no partial effects. This demonstrates
bounded publication acceptance; source ingestion and full document lineage have
separate acceptance coverage.

Two conservative limits remain in this native profile:

- Receipt acceptance requires the exact authenticated intake frontier. Receipts
  are not re-authenticated after intervening commits, including unrelated ones.
  Such a commit makes acceptance refuse; retained evidence remains readable and
  unconsumed. Acceptance is bounded to that commit context.
- Memory usage is the Linux process-wide lifetime peak RSS, a conservative upper
  bound. It is not per-invocation accounting or an enforcing sandbox. Earlier or
  concurrent allocations can make a small forecast return a memory
  `ResourceExhausted` receipt without a successful result.

`intervening_commit_refuses_without_consuming_receipt` and
`prior_process_rss_peak_refuses_small_forecast` exercise these refusal limits.
Post-demo improvements are tracked together in https://github.com/Norn-cloud/norn/issues/508.
