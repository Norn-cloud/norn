# Decisions: 2026-11-01

Status: adopted specification baseline; implementation is tracked independently in [core status](../../spec/core/README.md). [Owner] records explicit intent, [Astra] records the binding ruling/corrections, [Default] records a chosen implementation policy that needs a new decision to change. Unlabelled descriptions of existing files are observations, not directives.

## Thesis decisions

- [Owner] Derive applications and governed surfaces from one typed concept graph; reactive general-app DX must be competitive, with explicit effects and visible inherited guarantees.
- [Owner] Things and happenings are concepts. Workflows have states. Definitions form a thin generated meta-ontology; no reflective authority through catalog-row edits.
- [Owner] Author REA core physics in Norn; inventory/accounting/sales specialise it; jewelry composes them; apps configure packs. Nothing is “trust the core”.
- [Owner] Concepts bundle their facets. Laws attach to the governed concept/happening/pack/app; containment and specialisation retain them unchanged and only add restrictions.
- [Owner] Laws are theorem statements; definitions are axioms. Enforce by construction, then admission, then commit. Safety never depends on proof success.
- [Owner] Structured requirements and statecharts are expert-facing; EN/AR share one IR. Checker-generated statements feed solver backends; pack-owned Lean bodies may prove them.
- [Owner] Integrations are packs; observed behavior is ordinary mapped data; discovery and conformance are questions. Metrics follow typed additivity, with explicit business ratios.
- [Owner] Govern parameters and agents through ordinary actions. Only Functions behind `perform` admit external code. Demo scope is sell → scrap → melt.

## Corrections that override the DX sketch

- [Astra] Lower every writer, including imports, timers, migrations and synchronous triggered rules, to one checked effect closure; atomicity includes every immediate-law effect.
- [Astra] Bind cross-module laws to organisation/book/currency/valuation basis/account roles; never net unlike currencies.
- [Astra] Assay is a versioned observation plus explicit reconciliation; it cannot rewrite prior fine-metal balances.
- [Astra] Scrap exchange declares received metal AND payment/payable. Repeated independent assays and approval actions need real evidence paths.
- [Astra] Catalog Item is not a Holding. Object references are typed links or owned drafts; there is one reference model.
- [Astra] Aggregation needs grain/fan-out semantics. Balanced constructors do not prove arbitrary writers or account selection correct.
- [Astra] Report IR, admission, evaluator, commit enforcement, authoring and proof separately. An open PR or a declaration is not an implemented capability.

## Owner addition: data engineering and demo beat 6

- [Owner] Data engineering is first-class; scientists/engineers are a primary demo audience. The ontology is the semantic layer, and declarations generate pipelines rather than authored DAG code.
- [Owner] One query definition targets exact cell, incremental IVM and DuckDB/Iceberg (WellDB), with per-source cursors, freshness, grain and fan-out-aware aggregation.
- [Owner] Change feeds map source records with provenance/gaps; ML/heavy Functions return recorded outputs. Imported violations yield findings/quarantine, while governed commits refuse.
- [Owner] Bitemporal questions, backfills/restatements, what-if forks, source-document lineage and Iceberg/live/export/view outputs are required. Demo beat 6 includes guarded forecast/regression publication; see [acceptance](../../spec/acceptance/data-engineering.md).

[Default] Every spec's extension shape and diagnostic is a target contract, not a new root-kind authorization. Reuse existing types, extend strict decoding/schema/SDK together, and split implementation into coherent units that each merge on their own (no line cap; owner, 2026-11-08). Unsupported intermediate capabilities refuse.

[Default] Runtime safety-only releases are allowed only under an explicit admission profile that supports those exact predicates and keeps inherited assurance floors. Liveness is not a commit check. No evidence profile may drop a protected obligation.
